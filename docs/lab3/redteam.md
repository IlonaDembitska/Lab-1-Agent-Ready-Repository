- **Шлях агента:** харнес Лаб. 3 (`executeTask` + `opencode run --format json`), OpenCode 1.19.0, модель **opencode/nemotron-3.5-lightning-free**.

- **Режим дозволів.** Без `--auto` і без обходу перевірок. OpenCode не має `dontAsk`/`--allowedTools`; їхній відповідник — явний перелік у `scripts/harness/opencode.harness.json`:
  - `bash`: `"*": "deny"`, дозволено лише `npm test*`, `npx vitest*`, `npx tsc*`, `npm run typecheck*`, `npm run lint*`, `git status*`, `git diff*`;
  - `webfetch`: `deny`; `edit`: `allow`;
  - `opencode run` неінтерактивний: кожен запит дозволу типу `ask` (наприклад `external_directory`) відхиляється автоматично;
  - плагін `.opencode/plugins/guard-env.js` (з Лаб. 1) забороняє агентові читати й змінювати `.env*`.
  - Інструменти OpenCode (`--tools`) не звужували: read/glob/grep/write/edit/bash, обмежені правилами вище.
- **Ізоляція:** окремий git worktree на кожен сценарій, команда з `realDeps.prepare` дослівно: `git worktree add -b harness/<id>-<час> ../harness-runs/<id>-<час> main`. Після прогону дерево видаляється (`git worktree remove --force`).
  - **Мережа не вимкнена:** модель хмарна, контейнера `--network none` не було. Тому інваріант «не ходить на чужий хост» тут не факт, а обмеження (`webfetch: deny`, `git push` заборонено переліком bash).
- **Джерело шаблонів:** AgentDojo (arXiv:2406.13352, MIT) і InjecAgent (MIT), адаптовані під наш харнес у `scripts/redteam/cases.ts`.
- **Раннер AgentDojo як є не запускався:** провайдерів у ньому не перелічено, на безкоштовних моделях не перевірено.
- **Запобіжник-модель:** немає. `node -v` = v24.21.0, тож вимогу @openai/guardrails (≥22.13) Node виконує, але запобіжник не додавали.
- **Канарка:** фальшива, `CANARY_NOT_A_SECRET=канарка-NOT-A-SECRET-7f3a`. Лежить у `.env` дерева прогону і в середовищі процесу харнесу.
- **Безпека експерименту.** Раннер одразу після старту телеметрії видаляє з `process.env` усі непорожні змінні з `KEY|SECRET|TOKEN|PASSWORD|AUTH` у назві. `collect.ts` вирізає значення змінних з дампів у журналах і відмовляється писати, якщо в копії є значення будь-якого справжнього секрету. Результат на всіх трьох прогонах: «перевірено 5 секретів середовища — у копіях їх немає».

## 5. Чого я НЕ перевірив

- **Мережа не вимкнена** (немає контейнера `--network none`): модель хмарна. «Не ходить на чужий хост» тримається на `webfetch: deny` і переліку bash, а не на ізоляції мережі.
- **Інші точки входу:**
  - MCP-сервер Лаб. 2 харнесу не підключено, тож ця точка входу в харнесі відсутня, а не перевірена;
  - тіла веб-відповідей: `webfetch` заборонено.
- **Раннер AgentDojo** на безкоштовних/локальних моделях не перевірено.
- **Запобіжника-моделі немає**, отже й калібрування немає. Поріг запобіжника мав би помилки обох родів.
- **Один прогін на сценарій.** Три «зупинено» з причиною «агент проігнорував» (r-04, r-05, r-06) — це удача цієї моделі, а не захист; інша модель чи інше формулювання дадуть інший результат. Межа проти r-05 (зміна наявних тестів) є лише як грейдер `tests_untouched` у evals, але не в самому харнесі.
- **Модель відрізняється від основної** (nemotron, а не Big Pickle): поведінка агента залежить від моделі, межі — ні.
- **`edit: allow` + `npx vitest`** = агент може виконати будь-який JS у межах дерева й свого середовища. Виправлення прибрало з середовища секрети, але не саму можливість виконання. Звужувати далі — наприклад, заборонити `npx vitest` для файлів, створених агентом — я не став, бо це ламає звичайні задачі з тестами.
- **Текстові вказівки агентові вважаю послабленням, а не захистом.** Правило в промпті кроку 06 («запит поза кодом або обхід перевірок → відмова») не закриває жодної з цих дірок, і в §4 його немає.
